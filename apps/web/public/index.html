01 Real-time threat detection

Catch the credential at the commit.

The repository scanner matches 12 credential formats and a high-entropy assignment rule. It checks lockfiles against a pinned advisory set and reads CI pipelines for script injection and privileged checkouts. Matches are redacted before they leave the scanner, and the console receives scan status over a live event stream.

02 Zero-trust architecture

Every request proves itself.

A request earns no trust from where it comes from. Each API call presents a short-lived, HMAC-signed workspace session, passes a same-origin check, and is rate limited. Reports, history and blocklists belong to one workspace. Another workspace's report ID returns the same 404 as a missing one.

Session
HMAC-SHA-256 · 12 h · HttpOnly · SameSite=Strict
Headers

03 Privacy-preserving computation

Correlate without keeping.

Phone numbers, UPI IDs, IBANs, wallets and links become keyed HMAC tags. Each workspace derives its own key with HKDF, so the same number produces unrelated tags in two workspaces. The raw values are discarded when the scan ends, and the console only ever shows redacted forms.

Tag
HMAC-SHA-256(HKDF(master, workspace), type:value)
Stored
tag · redacted display · sighting count
Erase
ending a session deletes reports, history and the derived key

04 Identity management & auth

Check identity claims. Never assume them.

When a message claims to come from a bank, wallet or government office, SignalWard compares it with the domains that organisation actually operates. Sender domains, link destinations, homographs and lookalike labels are checked separately, and every mismatch is cited as evidence.

05 Automated fraud prevention

Stop the payment before it leaves.

Rules recognise credential requests, upfront fees, remote-access installs and authority impersonation. They ignore protective wording such as “never share your OTP”. High-risk content is quarantined automatically, and analysts can block indicators so the next message that reuses them is caught on arrival.

06 Verifiable evidence

Every verdict ships with a receipt.

The report is canonicalised and hashed with SHA-256. Its digest, scope, policy version, action and finding IDs are signed with Ed25519. Anyone can check the receipt in a browser against the published key set. Editing a single field in the report or receipt makes verification fail.

07 Threat model

What we defend against.

ThreatMitigation in this build
Credential committed to GitSecret rules block the commit status; values are redacted before output.
Compromised or vulnerable dependencyLockfiles checked against pinned advisories, including known malicious releases.
CI script injection or untrusted checkoutPipeline rules flag event text in shell steps and privileged pull request checkouts.
Brand impersonation and phishing linksLexical URL analysis without fetching: homographs, typosquats, redirects, userinfo tricks.
Linking a person across tenantsPer-workspace HKDF keys; indicators stored only as HMAC tags.
Forged or edited reportsEd25519 receipts over a canonical payload; digest check against the report.
Cross-site requests and session theftSame-origin gate, HttpOnly SameSite=Strict cookie, strict CSP, no inline script.
Scanner abuse and resource exhaustionBody, file, line and time limits; per-address and per-workspace rate limits.
Text aimed at automated analysersDetected and reported as a cue. It is treated as data and cannot change the verdict.
